# Phase 21.1: Repository Footprint and Download Size Reduction - Research

**Researched:** 2026-04-01
**Domain:** Reducing both source-distributed and local generated disk footprint in the APDR repo before the rest of v2.4 continues
**Confidence:** High

## Summary

Phase 21.1 should be treated as a footprint-correction phase, not as a generic cleanup sprint. The current repo has two distinct disk problems that need separate treatment. First, fresh source checkouts and GitHub downloads are inflated because generated Cargo target trees under `tools/apdr/target-*` are tracked in Git even though `tools/apdr/.gitignore` already says normal target and cache directories are local-only. Second, local working copies balloon because APDR still defaults heavy runtime cache data into `tools/apdr/.apdr-cache`, and common APDR build flows still produce large target directories inside the repo tree.

The local evidence is large enough that the phase should stay focused on the biggest seams rather than broad repo housekeeping. On 2026-04-01, `tools` is about `29G`, `tools/apdr/.apdr-cache` is about `15G`, and `tools/apdr/target` is about `6.7G`. In addition, multiple tracked `tools/apdr/target-*` trees are each hundreds of megabytes: `target-test-mecab` and `target-test-johnny` are about `801M` each, `target-fix-build` about `649M`, and several others range from `117M` to `518M`. Those tracked trees are not normal source assets; they are Cargo outputs, `.pdb` files, and dependency fingerprints that should never keep inflating source distribution.

The repo already has useful building blocks for the local-footprint half of the work. APDR exposes `apdr cache stats`, `apdr cache prune`, `--cache-path`, and the `APDR_CACHE_DIR` environment seam in existing code, and `scripts/cleanup-envs.sh` already proves the repo accepts purpose-built cleanup helpers when benchmark leftovers get too large. The planning implication is clear: Phase 21.1 should ship three bounded deliverables. Remove tracked target artifacts from source distribution and guard against regression. Move or resolve APDR cache defaults outside the repo tree while preserving explicit override paths. Then freeze a deterministic footprint checker and before/after artifact contract so the milestone can prove the repo is actually lighter rather than only better documented.

## Evidence That Should Drive Planning

### 1. The source-download problem is real because tracked APDR build outputs slipped into Git

This is not just a local ignored-cache problem. `git ls-files 'tools/apdr/target*'` returns multiple tracked Cargo output trees, and `git show --stat ca4a931 -- tools/apdr/target-fix-build ...` confirms they were introduced through a real commit rather than only local dirt. Those paths contain binary artifacts, `.pdb` files, `.d` dependency files, and fingerprint directories, which are all generated outputs.

Important implications:

- `tools/apdr/.gitignore` currently ignores `target/` but not `target-fix-*` or `target-test-*`.
- Source distribution will stay bloated until those tracked trees are removed from the index, not merely hidden by docs.
- The phase needs a regression guard so future target-style directories do not re-enter source control.

### 2. APDR still defaults heavy runtime cache data inside the repo tree

Two code seams prove this:

- `tools/apdr/src/lib.rs` sets `ResolveConfig::for_tool_root(...).cache_path` to `tool_root.join(".apdr-cache")`
- `tools/apdr/src/main.rs` parses `apdr cache ...` with the same in-tree default before optional `--cache-path` override

That means the repo grows by default during normal APDR use even though existing documentation already describes `.apdr-cache/` as runtime data. The phase should centralize default cache-path resolution so repo-local cache storage becomes an opt-in or explicit override instead of the default.

### 3. The local build-footprint problem is separate from cache growth

`tools/apdr/build.sh` still runs plain `cargo build --release`, so standard Unix build flow writes to `tools/apdr/target` unless the caller manually overrides `CARGO_TARGET_DIR`. The tracked `target-fix-*` and `target-test-*` directories also show that alternative target dirs were used without any guardrail preventing them from landing in Git.

Important implications:

- Cache cleanup alone is not enough; large Cargo output trees still need a supported reclaim path.
- The phase does not need a full Cargo architecture rewrite. A supported external target-dir default for helper scripts plus a cleanup tool is sufficient.
- A footprint proof should report cache bytes and target bytes separately so the repo can tell whether a gain came from source cleanup, local cache relocation, or both.

### 4. Existing cleanup surfaces are good starting points but not enough on their own

The repo already includes:

- `apdr cache stats`
- `apdr cache prune`
- `--cache-path`
- `APDR_CACHE_DIR` in `tools/apdr/src/resolver/family_knowledge/learned.rs`
- `scripts/cleanup-envs.sh` for benchmark-run leftovers

Those are good foundations, but none currently provide a single supported answer to: "Where did the bytes go, and how do I reclaim them safely?" Phase 21.1 should consolidate that into one operator-facing footprint story with deterministic checks.

### 5. The phase should distinguish source-distributed bytes from local generated bytes in its proof

The requirement wording and the user request point at two different pains:

- GitHub download and fresh checkout size
- local disk pressure after build and benchmark activity

If the phase proves only one side, it will look complete while leaving the other pain intact. The checker and proof artifacts should therefore track at least:

- tracked APDR target-style paths
- bytes under tracked source-distributed offenders
- local APDR cache bytes
- local APDR target bytes
- tool-tree total bytes or comparable repo-local summary

## Implementation Recommendations

### 1. Remove tracked APDR build outputs from source distribution and add a tracked-artifact guard

Recommended files:

- `tools/apdr/.gitignore`
- `scripts/check_phase21_1_footprint.py`
- tracked paths under `tools/apdr/target-fix-*` and `tools/apdr/target-test-*`

Recommended responsibilities:

- broaden ignore coverage from `target/` to `target*/`
- remove all tracked `tools/apdr/target-*` directories from Git
- add a checker mode that fails when tracked APDR target or cache artifacts reappear

### 2. Move APDR cache defaults out of the repo tree and add a supported cleanup path

Recommended files:

- `tools/apdr/Cargo.toml`
- `tools/apdr/src/lib.rs`
- `tools/apdr/src/main.rs`
- `tools/apdr/build.sh`
- `scripts/cleanup-apdr-footprint.sh`
- `tools/apdr/README.md`

Recommended responsibilities:

- centralize default cache-path resolution around `APDR_CACHE_DIR`, `--cache-path`, and a per-user cache location outside the repo
- add tests that lock the default-path and override behavior
- make the common build helper honor an external target dir by default
- add a cleanup helper that can report and reclaim APDR cache plus target bytes safely

### 3. Freeze a deterministic footprint proof contract

Recommended files:

- `scripts/check_phase21_1_footprint.py`
- `.planning/phases/21.1-repository-footprint-and-download-size-reduction/21.1-footprint-baseline.json`
- `.planning/phases/21.1-repository-footprint-and-download-size-reduction/21.1-footprint-candidate.json`
- `.planning/phases/21.1-repository-footprint-and-download-size-reduction/21.1-footprint-proof-status.json`
- `.planning/phases/21.1-repository-footprint-and-download-size-reduction/21.1-FOOTPRINT-DELTA.md`

Recommended responsibilities:

- capture a baseline snapshot of tracked offenders and local heavy directories
- capture a candidate snapshot after the cleanup/default changes land
- fail when tracked `target-*` paths remain, when local footprint metrics are missing, or when the baseline/candidate schema drifts

## Validation Architecture

### Quick checks

- `python3 scripts/check_phase21_1_footprint.py --repo-root . --mode tracked --status-json /tmp/phase21_1-tracked-status.json --probe-only`
- `cargo test --manifest-path tools/apdr/Cargo.toml phase21_1_cache_ -- --nocapture`
- `bash scripts/cleanup-apdr-footprint.sh --help`

### Artifact checks

- `rg -n 'target\\*/|APDR_CACHE_DIR|cache-path|APDR_TARGET_DIR' tools/apdr/.gitignore tools/apdr/src/lib.rs tools/apdr/src/main.rs tools/apdr/build.sh tools/apdr/README.md`
- `rg -n 'mode tracked|mode local|tracked_target_paths|local_cache_bytes|local_target_bytes' scripts/check_phase21_1_footprint.py`
- `rg -n 'tracked_target_paths|local_cache_bytes|local_target_bytes|tool_tree_bytes|repo_git_bytes' .planning/phases/21.1-repository-footprint-and-download-size-reduction/21.1-footprint-baseline.json .planning/phases/21.1-repository-footprint-and-download-size-reduction/21.1-footprint-candidate.json`

### Phase-close checks

- inspect `git ls-files 'tools/apdr/target*'` and confirm it returns no paths
- inspect the candidate footprint artifact and confirm it distinguishes tracked-source, local-cache, and local-target bytes instead of collapsing them into one number
- inspect the cleanup helper output and confirm it can report bytes without forcing deletion by default
