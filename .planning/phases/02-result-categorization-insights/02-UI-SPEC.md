## Performance Contract

Phase 1 targets (maintained in Phase 2):

- **UI-04:** Sustain **60fps** during result updates
- **UI-05:** Memory stable (<50MB growth over 30 min)

Phase 2 constraints:

- **Filter operations:** Client-side filtering must complete in <16ms (single frame) for up to 200 cases
- **Badge rendering:** Use CSS classes, not inline styles, for color changes (GPU acceleration)
- **Tooltip rendering:** Lazy-create tooltips on first hover, cache in DOM, toggle visibility thereafter
- **Expandable details:** Progressive rendering — only populate detail view when user expands case row

Implementation strategies:

- **Filter debouncing:** Search input debounced to 150ms to prevent excessive re-renders
- **Virtual scrolling:** NOT needed (max ~100 cases per panel per requirements)
- **Batch DOM updates:** Filter changes batch all case row updates in single `requestAnimationFrame`

## Phase 2 Specific: Cache Hit Dashboard Contract

### Layout

```
┌─────────────────────────────────────────────┐
│ Cache Hit Rate                              │
├─────────────────────────────────────────────┤
│ Tier1 (cache):     45/100 (45.0%)          │
│ Tier2 (heuristic): 30/100 (30.0%)          │
│ Tier3 (LLM):       25/100 (25.0%)          │
└─────────────────────────────────────────────┘
```

### Visual Treatment

- **Container:** `.cache-hit-dashboard`, --bg-panel background, 1px border rgba(122, 127, 138, 0.35), 20px padding
- **Grid layout:** 3 rows, single column, 8px gap between rows
- **Each metric:** `.tier-metric`, flex row, justify-content: space-between
  - **Label:** --blue color, bold weight, e.g., "Tier1 (cache):"
  - **Value:** --yellow color, bold weight, e.g., "45/100 (45.0%)"
  - **Alignment:** Label left, value right
- **Placement:** Above both result panels (Deterministic and LLM), below progress section

### Update Behavior

- Updates in real-time as cases complete (SSE-driven from Phase 1)
- No loading skeleton needed (starts at 0/0 (0.0%) and increments)
- Percentages displayed with 1 decimal place precision

## Phase 2 Specific: Badge Contract

### Confidence Badge

- **High (>0.7):** Green circle, 8px diameter, `background: var(--green)`
- **Medium (0.4-0.7):** Yellow circle, 8px diameter, `background: var(--yellow)`
- **Low (<0.4):** Red circle, 8px diameter, `background: var(--red)`
- **Display:** Inline before case status in table cell
- **Tooltip:** Shows exact score on hover, e.g., "High confidence: 0.85"

### Skip Badge

- **Icon:** ⊘ (Unicode 2298)
- **Color:** `var(--yellow)`
- **Display:** Inline after status in table cell (if case skipped)
- **Tooltip:** "Skipped: confidence {score} below 0.4 threshold"

### Tier Badge

- **Tier1:** Green text, "T1", inline in table cell
- **Tier2:** Yellow text, "T2", inline in table cell
- **Tier3:** Blue text, "T3", inline in table cell
- **Display:** In dedicated "TIER" column (new column added to table)

## Phase 2 Specific: Expandable Detail Contract

```

  tier1 cache → miss
  tier2 heuristic → match (namespace: sklearn → scikit-learn)
  tier3 LLM → not attempted
```

**Visual treatment:**
- Vertical list, each tier on separate line
- Arrow (→) separates tier from result
- Successful tier: --green color
- Failed tier: --muted color
